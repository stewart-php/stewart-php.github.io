MQTT

Apps can exchange messages with an MQTT server, for example to read Zigbee2MQTT devices directly or to talk to devices Home Assistant does not know. Stewart keeps one connection to the server, and apps ask for Mqtt in their constructor. Receiving

Section titled “Receiving”

watchMessages('zigbee2mqtt/+/temperature') returns a stream of MqttMessages with topic, payload (text), qos and retain. decodeJsonPayload() reads a JSON payload.

Topic filters use MQTT’s wildcards: + matches one level, # the rest. A filter that starts with a wildcard does not match $SYS/… topics.

Publishing

Section titled “Publishing”

publish($topic, $payload, $qos, retain: …) sends a message. A string payload is sent as it is, and an array as JSON.

QoS 0 and 1 are supported. A QoS 1 message published while the server is unreachable waits, up to mqtt.outbound_buffer messages, and is sent after the reconnect.

Watching the connection

Section titled “Watching the connection”

make status shows the connection on its mqtt row: connected since 5m ago, 1 reconnect, last outage 3s, or reconnecting since 20s ago: Connection refused, followed by the QoS 1 messages still waiting and how many messages were dropped. A message is dropped when it is QoS 0 and the server is unreachable, when sending it fails, when a full mqtt.outbound_buffer pushes out the oldest, or when the server keeps dropping the connection over it. The log warns about the first drop of each kind and then every 100th, with the count so far.

The same figures are metrics: stewart_mqtt_connection_phase{phase}, stewart_mqtt_reconnects_total, stewart_mqtt_messages_dropped_total{reason} and stewart_mqtt_outbound_queued; the metrics reference lists them.

Common problems

Section titled “Common problems”

MQTT is not configured. Set STEWART_MQTT__URL in .env.

Nothing arrives. Check the topic with an MQTT client, such as mosquitto_sub -h host -t '#' -v. Topics are case-sensitive.

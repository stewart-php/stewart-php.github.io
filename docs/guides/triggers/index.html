Triggers

Some moments are neither a state change nor an event: a person entering a zone, a template turning true, a calendar event starting. Home Assistant detects these with triggers, and watchTrigger() lets an app use them. This app turns the hall light on when Anna comes home and the ground floor off when she leaves:

watchTrigger() returns a stream of TriggerEvents, with the usual operators (filter, debounce, take, …).

Built-in triggers

Section titled “Built-in triggers”
Builder Fires
HaTrigger::onZoneTransition('person.anna', 'zone.home', ZoneTransition::Enter) When a person or device tracker enters or leaves a zone
HaTrigger::whenTemplateTrue('{{ … }}', for: Duration::minutes(2)) When a template turns true, optionally after it stayed true that long
HaTrigger::onTimePattern(minutes: '/5') On a clock pattern; hours, minutes and seconds each take '/n', '*' or a number
HaTrigger::atTime('07:30') Every day at that time
HaTrigger::atTime('input_datetime.wake_up') At the time an input_datetime or timestamp sensor holds
HaTrigger::onSunrise() / onSunset(SunOffset::before(…)) At sunrise or sunset

Each builder takes an optional id:, which comes back as $event->getTriggerId().

Prefer Stewart’s own tools where they exist. For times and the sun, a schedule keeps working while Home Assistant is unreachable; a trigger does not. For state changes, watchStateChanges() runs inside Stewart and needs no subscription in Home Assistant.

What a TriggerEvent holds

Section titled “What a TriggerEvent holds”
Method Returns
getTriggerId() Your id:, or the trigger’s position in the list
getPlatform() zone, template, time, …
getValue('to_state'), getTriggerData() Home Assistant’s trigger variables
$event->context Who caused it
$event->firedAt When Stewart received it

How triggers behave

Section titled “How triggers behave”
  • Shared. Apps that watch the same trigger with the same variables share one subscription in Home Assistant.
  • Outages. After Stewart reconnects, every trigger is subscribed again. A trigger that would have fired while the connection was down is lost.
  • Rejected triggers. Home Assistant checks a trigger when Stewart subscribes. If it refuses, Stewart logs Home Assistant’s reason and the subscription ends. The builders catch most mistakes earlier, with a TriggerException.
  • Home Assistant version. The builders need Home Assistant 2024.10 or newer. On older versions, pass arrays with platform: instead of trigger:.

Common problems

Section titled “Common problems”

The trigger never fires, and the log shows Home Assistant’s error. Home Assistant rejected the trigger. Try the same trigger in a Home Assistant automation to see the problem.

It missed a moment. The connection was down at that moment; triggers are not replayed. Use a schedule for times of day.

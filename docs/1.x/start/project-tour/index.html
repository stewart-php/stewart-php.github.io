These pages describe Stewart 1.x. Read the docs for the latest release, and how to upgrade.

Project tour

A new project from the skeleton looks like this. You mostly work in apps/, tests/ and stewart.yaml.

Your code

Section titled “Your code”

apps/ holds one class per automation. Every class with #[Automation] that implements App is an app; there is no list to keep up to date. The namespace is App. You can put other classes here too, such as value objects or helpers that several apps share.

tests/ holds PHPUnit tests, in the namespace App\Tests. make test runs them. See Testing apps.

generated/ holds classes that make generate writes from your Home Assistant: one per entity domain, with methods for its services. Commit them, so a build or a server never needs Home Assistant to create them. Run make generate again after you add devices. See Typed entities.

services.php registers your own classes, such as a weather API client, so apps can ask for them in their constructor. Leave it as it is until you need it:

Settings

Section titled “Settings”

stewart.yaml holds the settings that differ from the defaults, and the options of your apps. It belongs in Git, so keep secrets out of it.

.env holds secrets (the Home Assistant token) and settings that differ per machine. Every setting can live here instead of in stewart.yaml: write STEWART_, then the keys in capitals, joined by two underscores. log_level becomes STEWART_LOG_LEVEL, and home_assistant.token becomes STEWART_HOME_ASSISTANT__TOKEN.

To see every setting with its default, run make config-reference. To see what is in effect right now, run make config; secrets are masked.

Running

Section titled “Running”

compose.yaml runs two containers: stewart, from the ghcr.io/stewart-php/runtime image with your project mounted into it, and valkey, which stores what apps must remember across restarts. Valkey starts only while .env sets COMPOSE_PROFILES=store. The runtime image holds PHP and Stewart’s start-up script. Your code and the Stewart version come from your project.

compose.dev.yaml is added for development commands such as make run and make test. It uses the image with Xdebug, and installs dependencies only when you run make install.

Dockerfile and deploy/ are for servers. See Deploying.

.github/workflows/ runs make stan, make test and make check on every push (ci.yml), and builds an image of your project once they pass (image.yml). Dependabot proposes Stewart updates.

make commands

Section titled “make commands”

make help lists them all, and the command reference describes each with the stewart commands. These are the ones you use most:

Command What it does
make setup First run: pull images, create .env, install dependencies, check the container
make doctor Check the settings and the connections to Home Assistant and the store
make run Run in the foreground; Ctrl-C stops it. ONLY="porch-light" runs only those apps, TRACE=porch-light traces one, DRY_RUN=1 sends no service calls
make watch Like make run, and reloads after every saved change to the apps, services.php or stewart.yaml
make debug Like make run, with Xdebug on
make app NAME=… Create an app in apps/ and its test in tests/; TEMPLATE=1 creates an #[AppTemplate]
make test Run the tests
make stan Run PHPStan
make generate Write the typed classes from Home Assistant into generated/
make config Show the settings in effect
make config-reference Show every setting with its default
make check Check that the configuration loads and every app can be built, and list the apps with their workers
make sh Open a shell in the container
make up / make down Start Stewart in the background / stop it
make logs Follow the log of the background Stewart
make status Ask the running Stewart how its apps are doing. APP=porch-light adds that app’s subscriptions and schedules, WATCH=1 redraws every 2s
make app-pause APP=… / make app-resume APP=… Pause or resume one app of the running Stewart; make app-reset APP=… forgets the choice
make worker-restart WORKER=… Restart one worker of the running Stewart
make update Update dependencies within your Stewart version
make upgrade VERSION=… Move to another Stewart version

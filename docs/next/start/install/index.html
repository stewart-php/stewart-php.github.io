Install Stewart

By the end of this page you have a Stewart project on your machine, connected to your Home Assistant and running its example app.

What you need

Section titled “What you need”
  • Docker with Compose. PHP, Composer and everything else run inside containers, so you install nothing else. The images run on amd64 and arm64, so a Raspberry Pi 4 or 5 works too.
  • A Home Assistant you can reach over the network from the machine running Docker. Stewart is not a Home Assistant add-on: it runs in its own container, on the same machine or another one.
  • A long-lived access token from an administrator user. The next section shows how to make one.

1. Create a Home Assistant user for Stewart

Section titled “1. Create a Home Assistant user for Stewart”

Stewart works best with its own Home Assistant user. Its changes are then marked as Stewart’s, and an app can tell them apart from yours. For example, it can tell that you switched a light off by hand.

  1. In Home Assistant, open Settings → People and add a person, for example “Stewart”.
  2. Allow them to log in, and turn on Administrator. Stewart needs an administrator token to listen to all events.
  3. Log in as that user, open the profile page, go to the Security tab, and create a long-lived access token. Copy it now, because Home Assistant shows it only once.

Common problems

Section titled “Common problems”

The child config "token" under "stewart.home_assistant" must be configured. The token in .env is empty, or .env is missing. make env creates .env again from .env.example.

Stewart cannot connect. Check the URL from inside the container: make sh, then wget -qO- http://your-host:8123. localhost and 127.0.0.1 point at the container itself.

AdministratorRequired. The token belongs to a user without administrator rights. Turn on Administrator for that user, or create the token from an administrator user.

make is not found. On macOS, run xcode-select --install. On Debian or Ubuntu, run sudo apt install make.
